# 教辅后端第二三阶段执行细化

日期：2026年10月3日。依据既定五阶段计划，顺序完成阶段二再进入阶段三。用户已授权隔离模拟环境、每阶段多智能体验收及真实模型API测试。源码在本地镜像编辑，执行和验收在指定服务器；现有Hermes/OpenViking业务配置及第三方源码保持原状。

## 阶段二

1. 将现有规划提交逻辑独立为模块；添加可迁移的调度记录、任务租约和运行停用开关。
2. 对当前业务日生成唯一daily任务；来信、progress、原步骤和内部复核按已保存依据运行。普通答疑优先，不补发停机期间的过时主动消息。
3. 将模拟发送拆成持久准备、发送前复核、模拟渠道发起、回执记录。业务库和模拟渠道使用不同SQLite库，能够真实注入“外部已执行、业务结果尚未保存”的故障。
4. 任务领取和家庭执行串行化；过期运行不能继续写入。发送未知先查询原操作，保持原责任，不能盲目重发。
5. 频控仅启用明确标为simulation的测试配置。准备时预占，暂停/新来信/截止时间/停用在发起前重新核验；内部复核不等于重新联系。
6. 运行两日场景、并发及故障测试，再由独立智能体分别检查行为边界和实现质量。修复后复验，保存同一版本的运行证据。

Hermes原生cron可以作为后续唤醒入口；业务队列只承担家庭身份、事务、租约、报告和操作恢复，不另造模型框架。具体原生接入点先只读核实，再决定适配方式。

## 阶段三

阶段二验收通过后执行：补齐表格结构与来源映射；实现限定范围的知识读取、Skill和必读规范加载、service/daily/progress三配方、家庭记忆过滤及更正；核对并隔离运行Hermes原生工具/Skill/会话/取消能力。

课程绑定、数据覆盖与源时区未知时，保留待映射状态。模拟绑定用于验证机制，不包装成真实学员业务事实。复用现有课程/产品知识和原生工具注册方式，不修改vendor源码、不替换Hermes运行循环。

验收由实际服务器测试、真实模型工具调用与独立智能体复核共同构成。API调用不设人为额度上限，但每次调用要有清晰验证目标，避免无信息增量的重复运行。

## 代码和阶段门禁

按职责分离规划、队列、调度、发送策略、渠道、上下文和适配器。复用现有接口，扩展前先整理边界；不以大量特例堆到Application或单一脚本。只为可观察行为和重要失败场景增加测试。

可修复的一般问题在当前阶段修复；重大业务规则矛盾、无法保证的身份/权限隔离、必须大改Hermes才能成立的架构假设等阻止下一阶段的问题，记录复现、影响和可选方案，暂停开发交由用户判断。

每次交付同步Tool/Skill元数据、阶段计划、服务器源码、测试与模拟记录。代码通过、模拟通过、真实模型通过、真实渠道通过分别表述。

## 2026年10月2日：五项连续模拟

16步基线覆盖补课、课程答疑、人工核实、方法练习、阶段反馈，形成18次模拟发送和6个模拟媒体标识。10项程序检查通过；语义复核发现“核实时间被当成实际完课时间”和“语音送达被当成孩子听过”，据此修订共用规范，并澄清多课节暂停及核实部分收尾。

## 2026年10月3日：全量核对与三组模拟

### 结论与证据层次

现有内容可以进入单学生后端接入，但不能视为生产服务已验收。此前的“全量审核通过”低估了内容偏差，本轮直接对照原表后进行了修订。格式与引用检查覆盖41个目录；三组独立执行覆盖14个事件步骤、实际读取12个不同Skill，并产生13次模拟发送。工具和状态的27项检查通过，不代表全部话术和全部动作分支无缺陷。

| 层次 | 已完成 | 可以证明什么 |
| --- | --- | --- |
| 内容核对 | 三路智能体直接核对督学、互动、答疑和高光原文；首批既有项及公共收尾一起纳入映射 | 修订可逐项追溯，不以评审者印象替代原文 |
| 格式与依赖 | 41个Skill官方格式校验、必读规范声明与正文链接、原知识文件哈希 | 当前文件可解析，所声明的本地引用存在 |
| 模型行为抽样 | 三个执行者各自只获取当前事件、能力目录、Skill、知识及实际模拟工具结果，不拿预设答案 | 观察跨步判断、话术、工具调用和事项接续；没有把预写结果当模型输出 |
| 故障注入 | 删除隔离副本中的必读规范后调用模拟加载器 | 加载报错且未产生操作；不证明生产加载器或模型的错误恢复 |
| 后端运行 | 本轮未接入生产执行环境 | 无法证明Hermes/OpenViking发现与加载、真实媒体/消息/工单、并发队列或崩溃恢复 |

### 已修订内容

- 七日成就恢复为“7日内完成5天课程”，生日使用孩子真实生日；首课、整组首次全对、周冠军、晋档等条件分别核对，不能泛化为任意高光。
- 趣味互动恢复2—3题与孩子考家长；生活联想恢复故事情境交流，不能擅自变成必须完成的实践任务。感受分享恢复老师先分享及原语音长度要求。
- 补齐历史补读的范围、周收尾的“仅缺今日”、周末计划与周报分支、二维码/链接及孩子口信要求。
- 效果疑虑恢复可选A/B方案、48小时跟进目标和真人协作；普通儿童分享不一律按危机处理；退款提交、接单、进展承诺及最终退款分别记录。
- 八项新增互动/答疑入口补齐共用规范元数据和直接链接；名称别名只导航，不虚构已有生产触发器。详细约束合入正文，未保留“评审补充约束”拼接段。
- 模拟发现高光话术冗长、内部核验说明对客外露，以及一处将“收听未知”写为“未收听”。已修订共用服务规范，原运行证据保留，定向回归另存。

原动作、课程大纲、产品知识三份文件与既有基准哈希一致；未改写原知识。课程加工与OpenViking建设不在本轮修改范围。自动触发开关仍关闭。

每组9项工具与状态检查，共27/27。检查包括完成步骤、冻结输入未变、加载必读规范、先生成媒体再发、未重复提交同一草稿，以及各组特定边界。不同草稿表达同一意思、真正的并发幂等、话术是否自然，不能靠这些检查自动证明。

语义交叉复核另外发现：service首次互动记录将收听未知写为否定事实；主动候选以字符串记录，缺少部分目标Skill、来源、规则版本和去重依据。前者已补强共用规范并定向回归；后者作为后端候选记录的接入验收项，未在本轮臆造正式数据结构。高光初次消息也存在过度解释，不能将27项通过表述为整轮毫无问题。

questions复核发现语音待交付事项未显式保存负责人，恢复补发时也未留下必要性判断依据。本次外部恢复事件使交付完成，没有出现漏办，但不能据此认为责任记录完整。这两项与主动候选字段一起列入后端持久化校验，不能仅靠Skill文字保证。

### 定向回归

原始三组运行保留，不覆盖失败或不足。另建 `highlights-refined`（2步）和 `service-refined`（1步），均已执行完成，另14项通用工具与状态检查通过。执行者已知前轮背景，因此这些是回归验证，不属于新的盲测。

主审读取实际正文与状态后确认：高光文字由361字符缩至111字符，保留五课完成事实、鼓励和图卡待交付信息；未把内部工具故障或整段证据限制发给家长，原图卡在下一步补齐。字符数只是本次对比，不新增业务长度规则。互动回归明确保存 `listening_status=unknown`，下一步写“目前无作答记录，收听情况未知”，没有据送达判定听过或未听过。

合计执行17个事件步骤。三组原始运行与最终版本的差异仅为随后修订的共用服务规范；高光回归使用简洁表达修订版，收听状态回归使用其后的最终版。没有将旧运行改写成最终版全量通过；冻结输入和版本差异见[定向回归检查](../evaluations/service-skills-audit-20261003/refinement-checks.json)。

### 待接入与待确认

本轮只模拟单学生的串行事件。下一阶段实现一个最小后端闭环：事件进入 → 读取最新事项与消息 → 选择并加载Skill和知识 → 生成草稿或工具动作 → 发送前复核 → 保存回执与剩余责任。待办排队、即时咨询优先、暂停取消、未知回执查回，须由真实执行器和可查询状态共同保证。

需要继续验证：同一家庭异步新消息打断、并发发送与不同草稿重复语义、原操作失联和进程中断恢复、真实音频时长与质量、人工未接单和到期未更新、真实课表与版本匹配。榜单更正、21天勋章失败、成长视频超时长等未在本轮运行，不标为通过。

仍需业务确认的口径包括：连续缺课计数及48小时起算、连续学习的自然日/教学日、Q05的30分钟含义、首本与每本首次、严重缺课阈值、全局频控与例外。未确认内容不得被模型或开发补成生效规则。

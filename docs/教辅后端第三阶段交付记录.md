## 已实现

| 范围 | 实现与边界 |
| --- | --- |
| 学情与来源 | 八张源表全部保留来源坐标、结构行与学员行区别；SQL增加汇总、分组、AI题型/名称、按天作业、源行与可信课程绑定，共8张可查询表。旧批次重复导入可补齐扩展，不重复原事实。 |
| 正式适用性 | 课程/版本/教学日映射、时区、覆盖时间由宿主确认，模型无写入口。未知继续未知；变更课程版本清除旧课节映射。 |
| 知识与Skill | 知识固定版本及课节白名单，正文哈希核验，相邻课不补位；Skill通过Hermes原生只读接口加载正文与必读规范，限制角色、别名和文件范围。 |
| 家庭记忆 | 有来源的保存、更正、读取和删除；过期过滤，迟到旧消息不覆盖新偏好。删除清除记忆记录及历史中的正文，原聊天与备份不在本操作范围。 |
| 上下文 | service/daily/progress三配方；daily保留未完责任目录，progress仅绑定原报告与原事项，当前Control来自业务状态。 |
| Hermes | 保留原生AIAgent、工具注册、Skill读取、cron及interrupt。每次运行独立进程、profile、cwd和会话；实际工具集必须等于角色白名单。默认关闭内部材料进入模型。 |
| 调度接入 | 原生no_agent cron调用固定脚本，仅唤醒业务扫描，输出保持内部静默；默认paused，不启用生产常驻任务。 |

核心模块按数据、记忆、材料、上下文、工具桥、进程生命周期拆分。业务事务与身份控制留在后端；未复制Hermes模型循环，未修改vendor源码或已有服务配置。

## 验收证据及含义

程序回归已在指定服务器通过93项，无跳过。覆盖前两阶段、八表导入、旧库补齐、跨家庭SQL、记忆更正/删除、精确知识范围、必读规范、工具桥与Linux进程组清理。测试只读真实表格，模型场景只用虚构家庭。

真实API采用现有 `maas.qianwenaiapi.com / qwen3.8-flash`，通过Hermes原生循环运行六个场景：

| 场景 | 验收断言 |
| --- | --- |
| A1服务 | 当前家庭SQL仅3行；模拟微信回复包含有依据的行数，仅1个确认发送操作，并查询原操作。 |
| B、A2只读 | A→B→A三个独立profile/cwd；只读不改变家庭版本或操作；不能读到其他家庭校验词。 |
| daily | 实际提交唯一计划及指定模拟目标，服务写工具不在规划角色工具集。 |
| progress | 使用宿主夹具的合法来信证据，实际更新原事项并消费报告，目标和完成规则保持不变。 |
| cancel | 运行中撤销权限，原生interrupt发生，completed=false，不产生额外发送。 |

每个冻结场景保存实际工具调用摘要、成功/拒绝结果、内部最终输出、数据库断言和源码指纹，不将自然语言声称成功当作交付。10月3日基础验收未执行课程与Skill进入模型的分支，原始产物保留当时状态；10月4日授权后的补充结果见下节。服务器本地还核验了3次原生Skill读取（含别名和规划Skill）、课程与产品2份正文，相邻课读取被拒绝。

原生cron [独立运行证据](../evaluations/backend-stage3/native-cron-20261003T143111Z-f1e33703.json) 证明首次tick执行一次、再次零次、业务任务仅1条、消息/操作为0、原生execution成功且静默。首轮适配器误解析venv入口的问题已修复，失败记录保留。

多智能体审查见 [输入与记忆审查](../work/design-inputs/stage3-review.md)、[原生接入审查](../work/design-inputs/stage3-native-integration-review.md)。发现并修复了旧消息覆盖新记忆、课程换版继承旧映射、窗口配置漂移、异常原文进入日志、取消后权限残留和原生工具延迟加载导致白名单不一致等问题。

## 2026年10月4日授权后的材料联测

用户明确授权第1课正文、`explain-lesson` / `plan-proactive-service`及其必读规范发送至现有 `maas.qianwenaiapi.com / qwen3.8-flash`。在新隔离目录 `stage3-materials-20261004` 使用既有冻结源码运行3条真实模型链路，家庭、消息、学情继续使用虚构夹具。业务时钟保持原验收的2026年10月3日10:00，运行日期与模拟业务日期分开记录。

- service：实际加载`explain-lesson`、3份必读规范及`LESSON-L2-FOX-D01`正文，SQL只返回当前虚构家庭3行，完成1次模拟回复并查询原操作。模型没有将模拟课程绑定当成真实业务事实。
- daily：实际加载`plan-proactive-service`与`service-basics`，再提交唯一计划和指定模拟目标，没有消息发送。
- progress：实际加载同一规划Skill与规范，以合法来信证据更新唯一原事项；原目标、完成规则和剩余工作不变，报告已消费，未误标done。

3条链路合计14次API轮次，业务断言全部通过。独立复核精确比对工具参数和完整材料返回摘要、读取与提交顺序、实际业务记录及冻结来源。此次不修改Python源码或Hermes；原93项程序回归保留对应冻结版本，未重复执行无变化的检查。默认运行入口仍关闭材料加载，本次通过显式`--materials`在已授权测试中启用。

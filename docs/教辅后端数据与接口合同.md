## 通用类型和可信边界

| 类型 | 约定 |
| --- | --- |
| ID | 非空、不透明字符串，由后端分配或从已验证外部身份映射；样例ID仅供演示 |
| version与revision | 从1开始的整数；已有记录更新递增；不使用本地时钟作为版本 |
| timestamp | 带时区的时间字符串；存储统一标准化，服务日按Asia/Shanghai推导 |
| business_date | YYYY-MM-DD；daily任务按家庭与该日期唯一 |
| nullable | null表示未知或无值；空列表表示已确定没有条目；缺失必填字段不等于null |
| EvidenceRef | source_type、source_id、source_revision、可空locator；由程序核实来源存在与适用范围 |
| TimeConstraint | 原话、来源、日期、时段/精度、可空exact_at；只有明确精确时刻才填exact_at |
| RecordRef | record_type、record_id、version；指向业务快照，不替代原始证据 |

精确期限字段`due_at`只保存已知精确时刻。“明晚”使用TimeConstraint保留日期与时段，不偷偷补成21:00；内部`review_at`独立配置，也不成为家庭承诺。

可信调用信封由后端绑定：`request_id`、`actor_kind`、`family_id`、`run_id`、`capability_scope`。它不由模型自由填写。模型提供业务参数，工具桥接附加可信信封；任意资源ID仍要核对家庭归属，不能只相信信封或模型自报身份。

模型输出严格拒绝未知字段、错误枚举与越权字段，数组按标识去重；局部更新的“未提供”表示不改，“显式null”仅在字段可空时表示清除。禁止接收任意字典覆盖数据库整行。

## 状态记录与字段归属

### ServiceEvent

| 字段 | 类型和含义 | 修改者或约束 |
| --- | --- | --- |
| event_id、family_id、uid | ID | 后端生成并绑定，不可改 |
| goal_key、goal_type、target_scope | 稳定目标键、目标类别、课程/原课节或反馈周期范围 | daily建立；progress不能换成独立目标 |
| goal_text | 目标的可读说明 | 可澄清文字但不改变结构化目标；语义变化需按目标边界拒绝或待规划 |
| completion_kind | goal或delivery | 建立后不可降低或切换来结案 |
| completion_rule | 有类型的规则参数 | 本节下表；仅使用程序注册的判定器 |
| requirement_revision | 正整数 | 内容要求实质更正时由后端递增；保留更正依据和历史 |
| status | pending、in_progress、waiting、done、cancelled | 由有效daily/progress提交改变 |
| progress_facts、evidence_refs | 已接受事实和证据引用 | 建议与事实分开；不移除已发生事实 |
| remaining_work | 带work_key的未完成要求列表 | 仅原目标内的剩余内容；独立目标进待规划 |
| next_action | ActionSpec或null | 动作与原目标绑定；done/cancelled必须为空 |
| waiting | WaitingSpec或null | waiting时必填；其他状态通常为空 |
| due_at、due_constraint | 精确期限或时间约束 | 有效改约才能替换，原期限/逾期历史保留 |
| proposed_change | 变更内容、原值、依据、接受条件、状态，或null | 提议送达不等于已接受 |
| delivery_parts | 必要交付组成列表 | part_id稳定；独立新服务不能伪装成一部分 |
| service_hint | 可空方法建议 | 不覆盖完成规则、暂停与工具权限 |
| version | 正整数 | 后端成功提交时递增 |
| update_pending | 只读派生标记 | 根据未处理的有效报告版本计算，模型不能直接设false |
| canonical_event_id | 原ID或合并后保留的ID | 仅daily合并改变映射；不增加第六种业务状态 |

首批完成规则如下；未接入的规则类型不得自动结案。

| rule.type | 必填参数 | 后端校验 |
| --- | --- | --- |
| lessons_completed | lesson_refs、accepted_source_policy | 每个原课节存在当前适用完课证据；未知完成时间保留null |
| required_parts_confirmed | recipient_ref、required_part_ids、required_stage、requirement_revision | 所有必要部分在同一适用要求下达到渠道能证明的阶段 |

`ActionSpec`包含`step_id`、`action_kind`、`target_refs`、`purpose`、`not_before`、`source_refs`、`status`。action_kind首批限定为`verify_learning`、`verify_operation`、`clarify_existing`、`remind_makeup`、`deliver_feedback`；扩展类型需要配套工具权限和验收。新步骤可在原目标内建立，但不能通过反复更换step_id绕过既有操作与频控。

`WaitingSpec`包含`reason_code`、`reason_text`、`resume_conditions`、可空`review_at`及其来源。条件首批支持新消息、原操作新回执、适用学情更新和内部复核时刻。条件满足仅授予核验资格；暂停解除与对外许可另判。

### Event迁移表

| 当前状态 | 可转状态 | 依据和附加条件 |
| --- | --- | --- |
| 无 | pending、waiting | 只由daily创建；waiting需说明当前不能推进的原因 |
| pending | in_progress、waiting、done、cancelled | 有报告或daily证据；领取任务本身不变成in_progress |
| in_progress | in_progress、waiting、done、cancelled | 新事实支持继续、等待、完成或有依据取消 |
| waiting | waiting、in_progress、done、cancelled | 原目标核验或有效反馈；计时器到点本身不解除等待 |
| done | waiting、in_progress | 仅权威更正推翻原完成依据，经更正报告或daily重评；保留完成历史 |
| cancelled | cancelled | 首版终态；误取消恢复需受控修复记录，不由普通服务擅自重开 |

无变化可保持原状态并记录已消费输入。暂停Control独立于上述状态：即时暂停时Event可暂仍是in_progress，但发送已被拦截。完成和取消都须保存依据，不能因预算耗尽、跨日或无回复自动进入终态。

### 计划和进展报告

| 对象 | 字段 | 不变量 |
| --- | --- | --- |
| DailyPlan | plan_id、family_id、business_date、timezone、daily_run_id、revision、items、commit_id | 当天唯一成功提交；revision更新不意味着重新daily |
| PlanItem | item_id、event_id、rank、action_window、当前步骤/结果视图 | 提交后成员和rank固定；progress只更新原条目，视图读取当前Event |
| ServiceProgressReport | report_id、revision、origin_run_id、event_ids、facts、suggested_update、remaining_work、evidence_refs、operation_refs、input_coverage、supersedes_revision | 每版载荷不可变；event_ids必须已经存在 |
| ReportResolution | report_id、revision、event_id、resolution、commit_id | 按精确事项记录消费；resolution为applied、absorbed_daily或superseded |
| PendingPlanningInput | input_id、source_message_refs、raised_at、original_deadline、request、done_work、remaining_work、disposition、linked_event_ids | disposition为pending、linked、created、not_adopted；每种消费决定有依据 |

首版一次progress提交覆盖该报告的全部event_ids，并在一个家庭短事务内原子应用；每个事项各自判断完成。daily吸收也以完整报告版本为单位，避免半个报告被两条路径分别消费。不同报告可以独立提交。多事项消费仍逐项记录，便于派生各Event的update_pending。

若新revision替代旧revision，必须声明覆盖关系和完整保留的事实范围。另一个独立report_id到达不自动替代旧报告。update_pending仅在该Event已无未解决的有效报告版本时清除。

### 消息控制和操作

| 对象 | 最小字段 | 写入规则 |
| --- | --- | --- |
| Message | message_id、channel、external_message_id、family_id、received_seq、occurred_at、received_at、body/media_ref、source_revision | 渠道身份去重；外部编辑追加修订，不覆盖原话 |
| MessageCoverage | message_id、source_revision、intent_id、范围定位、interpreted、reply_operation_refs、remaining_question | 理解与已回复分开；剩余问题不因摘要消失 |
| Control | control_id、scope、action_kinds、status、source_refs、effective_at、resume_condition、version | status为active/released；解除需独立有效依据，不能自动随日期变化 |
| Operation | operation_id、purpose_key、family_id、run_id、step/intent关联、recipient_ref、content_revision、payload、payload_digest、event_part_bindings、basis_versions、stage | 外部发起前保存；正文、收件对象和声明动作必须一致 |
| OperationAttempt | operation_id、attempt_no、lease_token、reserved_at、last_checked_at、dispatch_started_at、ended_at、outcome | 发送尝试与模型尝试分开；每次外部发起可追溯 |
| Receipt | receipt_id、operation_id、channel_receipt_id、external_operation_id、source_seq、observed_at、occurred_at、stage、raw_ref | 追加保存；重复回执幂等，乱序不降级已确认结果 |

`purpose_key`绑定原交付义务或消息意图，不依赖草稿文字、Skill别名、run_id和日期。渠道重试沿用operation_id和外部幂等键；实质更正后的补交另有明确义务与更正依据，不能用改写草稿假造新义务。

prepared且没有发送可能性时可追加content_revision并重新校验；一旦存在dispatch_started或不确定发起事实，该次payload保持不可变。原操作确定未发送后的修订也必须留存旧版本，不能更改可能被渠道按幂等键缓存的载荷；具体重试能力由渠道合同决定。

## 输入合同与样例

### 学情标准化

用户已提供data/表格数据.xlsx，结构与字段映射见[实际输入对齐](教辅输入对齐与学情映射.md)；真实在线接口尚未提供。内部`LearningSnapshot`包含family_id、uid、snapshot_id、retrieved_at、source_revision、courses。每个课程分别保存course_ref、coverage_through、lessons和missing_fields；每个课节保存lesson_ref、completion_status、可空completed_at及EvidenceRef。样本无法完成课程绑定时，先留在ImportBatch/DayLearningRecord待映射层，不伪造course_ref或lesson_ref进入正式完成判定。

completion_status只接受completed、incomplete、unknown。源接口缺字段时映射unknown，不映射incomplete；不同课程覆盖时间不能用一个最晚时间覆盖。课表、请假和缺课阈值未知时规则返回`insufficient_data`或`rule_unconfirmed`，不生成可自动执行的缺课判断。规则版本不创造新目标或第二次交付资格。

作业/伴读另外保留submitted、not_submitted、not_configured、unknown，不能把无配置当作漏交。源表已提交但次数0的冲突保留标记，不覆盖原值；AI引导语、回答轮数、作品引用共享原始证据根。导出时间、可靠覆盖时间、完成实际时刻与提交时间分别存储。

### 原事项进展样例

以下均为虚构样例。可信信封中的family_id和run_id由后端附加，模型只提交payload。M-demo-1、E-demo-1等须在测试夹具中先建立；本示例不假定现实记录存在。

```json
{
  "request_id": "req-demo-progress-1",
  "family_id": "family-demo",
  "run_id": "run-demo-service-1",
  "payload": {
    "report_id": "report-demo-1",
    "revision": 1,
    "event_ids": ["E-demo-1"],
    "facts": [{"kind": "parent_report", "text": "孩子生病，家长要求暂停催课", "evidence_refs": [{"source_type": "message", "source_id": "M-demo-1", "source_revision": 1, "locator": "intent-pause"}]}],
    "suggested_update": [{"event_id": "E-demo-1", "status": "waiting", "reason": "等待家长反馈恢复情况"}],
    "remaining_work": [{"event_id": "E-demo-1", "work_key": "lesson-demo-3-completion", "description": "原课节尚无可靠完成证据"}],
    "evidence_refs": [{"source_type": "control", "source_id": "control-demo-1", "source_revision": 1, "locator": null}],
    "operation_refs": [],
    "input_coverage": [{"message_id": "M-demo-1", "source_revision": 1, "intent_id": "intent-pause", "interpreted": true, "reply_operation_refs": [], "remaining_question": null}],
    "supersedes_revision": null
  }
}
```

工具确认report已入库，不能返回Event已等待，除非后续progress确已提交。该报告只覆盖暂停意图，同一消息的入口问题必须有另一Coverage记录。

### ProgressProposal样例

模型只输出`event_updates`。report身份、允许event_ids和expected_versions由运行后端绑定，组合成如下内部提交对象；示例使用全字段检查的结构化changes，不接受任意补丁路径。

```json
{
  "commit_request_id": "commit-request-demo-1",
  "run_id": "run-demo-progress-1",
  "binding": {
    "mode": "progress",
    "report_id": "report-demo-1",
    "revision": 1,
    "family_input_version": 12,
    "expected_event_versions": {"E-demo-1": 3}
  },
  "event_updates": [{
    "event_id": "E-demo-1",
    "changes": {
      "status": "waiting",
      "waiting": {
        "reason_code": "family_pause",
        "reason_text": "家长要求暂停催课",
        "resume_conditions": [{"kind": "new_message", "subject_ref": "E-demo-1"}],
        "review_at": null,
        "review_time_source": null
      },
      "next_action": null,
      "service_hint": "先关心恢复情况，正常回答当前课程问题"
    },
    "evidence_refs": [{"source_type": "message", "source_id": "M-demo-1", "source_revision": 1, "locator": "intent-pause"}]
  }]
}
```

changes未提供remaining_work与期限，表示保留原值；不能清空未完成课节。存在适用Control时，任何resume_condition都不自动解除它。

### DailyProposal结构

daily输出限定为：`existing_event_updates`、`new_events`、`merges`、`plan_items`、`report_decisions`、`pending_input_decisions`、`unresolved_gaps`。新事项先用本次唯一client_ref引用，后端校验后分配正式event_id并在提交回执返回映射；不能由模型虚构已持久化ID。

所有输入报告和待规划需求必须出现在消费或保留决定中。报告可absorbed或retained，待规划输入可linked、created、not_adopted或retained；不采用须说明依据，retained须保留责任。完整目录扫描未结束时拒绝提交，不因模型上下文截断默默漏掉旧事项。

plan_items仅引用原Event或本次new_events的client_ref，rank唯一。当天daily成功后禁止另一份提议覆盖成员；晚到数据不再次daily。progress修改原条目无需重新生成全日计划。

## 应用接口

下表的调用者由后端验证。业务方法可先是Python内部接口；是否映射为工具、HTTP或WebSocket由适配器完成。

| 接口 | 调用者与必需参数 | 成功结果和原子写入 |
| --- | --- | --- |
| ingest_message | 可信渠道；外部消息身份、来源、内容 | Message、入站序号、未解释输入标记及服务Job同事务写入 |
| ingest_learning | 学情适配器；源版本、覆盖范围、数据 | Snapshot、指标结果和原事项待核验标记；不直接产生Planner Job |
| run_daily | 调度器；family_id、business_date | 创建或恢复唯一daily Job；已成功则返回原plan/commit |
| apply_control | 服务角色；request_id、范围、操作类型、证据 | Control立即生效、版本推进、相关旧草稿失效；返回提交回执 |
| record_pending_planning | 服务角色；request_id、原消息、要求和剩余工作 | 保存或幂等返回PendingPlanningInput；不建Event |
| submit_service_progress | 服务角色或原动作恢复器；report_id、revision、报告 | 不可变Report、相关待更新标记和progress Job同事务写入 |
| run_progress | 报告处理器；report_id、revision | 同业务任务重用，生成新的运行尝试；不重复消费报告 |
| commit_daily | daily运行提交器；提议与后端绑定 | Event、Plan、合并映射、消费记录、CommitReceipt原子写入 |
| commit_progress | progress运行提交器；提议与后端绑定 | 关联Event、原计划视图、消费记录、CommitReceipt原子写入 |
| claim_existing_step | 调度器；家庭、当前时间、执行种类 | 返回step、租约和事实版本；种类区分内部核验与主动服务 |
| prepare_operation | 服务角色；purpose、目标、最终内容、动作声明、证据 | 保存Operation，检查原义务已有操作；prepared不表示允许发送 |
| request_dispatch | 服务角色申请、执行器实施；operation_id、content_revision | 资格检查、发送预占、OperationAttempt；返回真实阶段或待核实 |
| reconcile_operation | 内部执行器；operation_id | 查询原操作，追加回执和归一化阶段，必要时补齐原报告 |
| query_commit | 绑定家庭的服务角色；request_id或commit_id | 返回实际提交及记录版本；不存在时不猜测已生效 |

`query_operation`独立返回操作阶段。query_commit查到“发送申请已处理”，不能解释成实际已送达；必须检查操作证据。返回字段只暴露当前角色所需信息，服务角色不读取Planner内部推理。

服务运行的最终结果另用ServiceOutcome保存action_taken、no_contact、waiting、needs_input或draft_only，附operation_refs、report_refs与remaining_coverage。该结果不直接外发，不作为Event状态；teacher_draft仅返回内部草稿，未执行request_dispatch不算发送。这两个要求来自本轮用户提示词对齐。

### 统一结果格式

结果的`outcome`取applied、duplicate、queued、rejected。queued仅表示持久等待；外部结果未知时返回data.stage=unknown而非通用失败。成功与重复结果均返回原持久标识和版本，失败带错误码及明确恢复动作。

```json
{
  "request_id": "req-demo-progress-1",
  "outcome": "queued",
  "data": {"report_id": "report-demo-1", "revision": 1, "job_id": "job-demo-progress-1"},
  "record_versions": {"family_input_version": 12},
  "error": null
}
```

```json
{
  "request_id": "commit-request-demo-1",
  "outcome": "rejected",
  "data": null,
  "record_versions": {"family_input_version": 13},
  "error": {
    "code": "STALE_INPUT",
    "message": "读取后出现新的适用输入",
    "recovery": "reload_and_reevaluate",
    "retry_same_payload": false
  }
}
```

### 错误分类

| code | 含义 | 恢复行为 |
| --- | --- | --- |
| INVALID_SCHEMA | 缺字段、错类型、未知字段 | 修正提议；不清除报告 |
| ROLE_FORBIDDEN / FAMILY_SCOPE_MISMATCH | 角色或家庭范围越权 | 拒绝，保留审计；不自动重试 |
| PROGRESS_SCOPE_VIOLATION | 新目标、非关联事项或今日成员变动 | 拒绝；独立需求走待规划 |
| IDEMPOTENCY_CONFLICT | 同身份不同载荷 | 拒绝，检查调用方；不得覆盖原值 |
| STALE_INPUT / STALE_EVENT | 输入或Event版本落后 | 重新读取后生成新尝试，不重放旧提议 |
| EVIDENCE_MISSING / EVIDENCE_SUPERSEDED | 缺少或失效依据 | 保存核实责任，取得新证据后恢复 |
| DAILY_ALREADY_COMMITTED | 当天已成功且试图提交另一提议 | 返回已有计划标识，拒绝覆盖 |
| WINDOW_CLOSED / CONTROL_ACTIVE | 当前不可外发 | 返回阻止原因与可空next_check_at，不承诺恢复时刻 |
| UPDATE_PENDING / INPUT_UNRESOLVED | 原事项待更新或有未解释来信 | 主动外发暂缓，继续独立答疑/必要核验 |
| OPERATION_UNCERTAIN | 该义务已有未知操作 | 查询原操作或人工核实；不可换ID发起 |
| RUN_REVOKED / LEASE_EXPIRED | 旧执行者失效 | 晚到输出不得取得副作用权限 |
| CAPABILITY_UNAVAILABLE | 所需知识、媒体或渠道能力未接通 | 保留未完成部分，不伪造完成或自动降级标准 |

错误是否可重试由后端类型与当前状态决定，不接受模型给出的retryable字段作为授权。

## 幂等并发与事务

### 三种身份不得混用

| 身份 | 稳定范围 | 重试时的变化 |
| --- | --- | --- |
| 业务任务 | daily为family/date；progress为report/revision；步骤为原目标内step_id | 恢复不改变业务身份 |
| 模型尝试 | agent_run_id、attempt_no、context_manifest | 冲突或失败重评可产生新尝试；旧授权撤销 |
| 对外操作 | operation_id、purpose_key、外部幂等键 | 未知结果核实原操作，不因模型重跑更换 |

报告载荷与规划提议是不同对象。相同report/revision重复入库只能是同一内容；其Planner第一次输出过期后，可基于新状态生成不同提议，使用新的commit_request_id与run_id。精确报告只能有一次有效消费；新的提议不覆盖已经成功的提交。

每个写接口先验证调用者范围，再查同request_id的已持久结果：相同载荷返回原回执，不再执行状态变更；不同载荷报冲突。新请求才继续当前版本检查。这样成功提交后客户端超时重试，不会因为版本已增加而误报未成功。重放授权仅允许查回原结果，不恢复已撤销run的新操作权限。

### 版本和提交

建议`family_input_version`在新消息、适用控制、真实报告、权威更正、学情有效变化及业务提交后增加。完全重复输入、只追加诊断日志和租约心跳不增加。首版宁可保守重评，不先做复杂细粒度依赖优化。

服务自身刚写入Control或报告后，必须读取工具回执刷新版本并重新检查受影响事实；不能仅把版本号改大继续发送旧稿。Planner的expected_versions由后端快照绑定，模型不能自称“已用最新版本”。

单家庭短事务应用提交，网络与模型调用在事务外。对事件、计划、报告消费和回执，要么全部成功，要么全部不生效。事务失败后原Report与Operation事实仍在；状态应用失败不抹掉已经发生的外部动作。

### 发送预占和频控

发送检查除家庭版本外，还检查当前时间、收件对象、适用Control、未解释新输入、原义务操作和有效执行租约。频控按已生效规则计算；同一短事务预占额度，两个执行者不能各自看见同一个剩余额度。对可能已发起的unknown保留预占直到有依据核实，不因超时释放后再发。

未发起且明确失效的预占可释放；已发生交付保持计数。频控口径未确认时不启用对应主动服务，不能偷偷套用配置样例。家长当前答疑按其实际动作检查，不机械占用未经确认的主动消息额度。

新来信先入库并设置未解释标记，同家庭旧主动草稿暂缓。服务解释并落实明确暂停后，独立答疑可基于新的输入覆盖申请发送；不是等整个家庭所有报告清空后才答复。

## 操作迁移和恢复表

| 当前阶段 | 允许的后续阶段 | 证据或限制 |
| --- | --- | --- |
| prepared | dispatching、cancelled | 真正发起前再次检查资格；取消需确定未发起 |
| dispatching | accepted、sent、delivered、failed、unknown | 渠道实际响应；崩溃或超时无法判定时用unknown |
| accepted | sent、delivered、failed、unknown | accepted仅受理，不满足sent/delivered标准 |
| unknown | accepted、sent、delivered、failed | 原操作查询或可靠回执；重查仍未知就保持 |
| sent | delivered或保留sent | 迟到unknown不降级；可靠投递失败另存delivery_failure事实 |
| delivered | delivered | 追加后续阅读等事实，不从送达推导满意或掌握 |
| failed | 保留failed，或受控重试进入dispatching | 必须确定原请求未执行且渠道允许同操作安全重试，仍检查窗口等条件 |
| cancelled | cancelled | 普通恢复不能重发；新的真实责任需重新取得资格 |

若渠道后续出现与已确认状态冲突的权威纠正，追加receipt_conflict/纠正记录并冻结完成判定，由适配器按该渠道的已验证语义处理。不可用简单枚举大小比较所有结果，也不可一律吞掉真实的迟到失败。

为了恢复“发送成功但报告未写”的中断，prepare_operation保存拟报告身份及原Event绑定。恢复器只把该操作的事实补齐到原服务结果；不能从任意回调新增规划入口。普通答疑无关联Event时仅补齐消息覆盖。

Job使用ready、leased、retry_wait、succeeded、needs_attention、superseded。租约过期的内部计算可重新领取；对可能已经发起的发送必须先转核实。租约令牌逐次改变，旧执行者写结果时不能越过当前持有者，也不能重复发起。所有未知外部结果仍可作为事实入账，不因原运行过期而丢弃。

## 上下文与适配器合同

### 三类上下文清单

| 配方 | 必需清单 | 输出限制 |
| --- | --- | --- |
| service | 任务、当前消息范围、关联Event、完成标准、Control、Operation、窗口、Skill及必读规范 | 回复/受控动作、进展报告、待规划记录 |
| planner_daily | 全部未完成责任目录及扫描覆盖、未消费报告/需求、指标与缺口、约束、昨日真实结果 | DailyProposal，不直接对外执行 |
| planner_progress | 精确report/revision、允许event_ids、原Event版本与证据、Control和计划条目 | ProgressProposal，只更新绑定原事项 |

`ContextManifest`保存来源ID/版本、读取覆盖、Skill/规范版本、提示词版本、权限集、窗口配置版本。必需约束不进入任意top-k裁剪；缺完整责任目录或必读规范时返回明确错误与恢复入口。

模型适配器至少返回run_id、终止原因、工具调用记录、提议/答复、实际用量（若能取得）和未完成范围。未知用量保留未知；不能以最终自然语言“已经发送”作为操作事实。取消运行后撤销工具授权，晚到内容只能留存审计。

### 渠道能力声明

ChannelCapabilities至少声明：是否支持幂等发送、是否可按operation_id或外部ID查询、回执可证明的阶段、是否有回执顺序号、是否支持取消在途请求、消息编辑语义。能力未验证记unknown；不按渠道名称臆测。

测试渠道必须支持配置accepted后超时、迟到sent、重复/乱序回执、确定未发送、永久unknown和发起前后中断。其成功仅证明后端按模拟合同运行，不能替代真实渠道验证。

知识适配器分开配置公共课程/产品范围与家庭记忆范围，返回正文及来源版本。已知课节优先映射直读；检索结果必须核实家庭、版本和知识范围。真实资料或提示词未就绪时用显式测试夹具，不能将测试内容作为正式输入。

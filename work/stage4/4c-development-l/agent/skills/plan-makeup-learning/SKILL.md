# 补课规划与跟进

了解孩子暂未学习的原因，帮助家庭找到适合的补课安排，并接续核实结果。主动触发只表示需要评估，联系、等待或人工协助取决于当前家庭情况。

## 使用前读取

读取[服务基本要求](../../guides/service-basics.md)和[督学规范](../../guides/supervision.md)，从[服务规则](../../config/service.yaml)读取 `makeup_learning`、`supervision` 与 `contact`。同次运行已经提供的完整、有效内容可以直接使用。

先确认当前时间和时区、学生及家长服务关系、运行模式与允许使用的工具。核对班期课表、应上课节、完成记录与数据更新时间，再读取相关家长消息、已有补课事项、近期联系、有效暂停和约定。

## 判断现在需要做什么

- 发现零完课或连续缺课时，核对信号对应的实际课节和生效规则，关联已有事项。没有已确认的触发阈值时，不自行选择一个数字启动自动催课；家长或老师提出的补课请求仍可处理。
- 已经完课或数据不足以确认缺课时，先核实状态。学习数据尚未同步时保留待核验，不认定家庭没有履约。
- 家长已说明原因时直接据此安排，不重复询问。存在有效补课约定时等待相应节点；约定被变更时更新原事项和复核安排。
- 有适用的暂停要求时，停止范围内的主动促课并保留事项。暂停单独保留来源、作用范围、生效时间及已明确的恢复条件；未知恢复时刻不自行补充，补课约定到期也不自动解除暂停。家长主动提出的新问题仍正常回应。
- 恢复条件保留家长原话和原意。涉及多个课节且表述含糊时，不把任一课开始或完成解释为整个范围的暂停解除；未明确的恢复条件继续待确认。
- 确实需要联系时，结合近期沟通、频控和家长可用时间，准备本次询问或建议。

## 商量补课安排

先以关心的方式了解困难，再结合家庭给出的时间提供周末或其他空闲时段的补课建议。把已经知道的原因和安排接起来，不预设孩子不愿学或家长不配合，也不替家长答应一个时刻。

制定安排前，读取原缺失课节的课程内容。当前可从 [L2课程资料](../../../knowledge/lesson/【数字员工】L2-课程大纲.md)定位对应“第几天”，取得剧情衔接、学习重点与适合介绍的亮点。通过 OpenViking 读取时同样核对级别、书目、课程版本和原课节。周五补第二课，仍使用第二课内容。

给家长的私信包含关心式询问或对已知困难的回应、具体补课建议，并嵌入给孩子的鼓励口信。初次促课文案的长度、昵称和课程内容要求见服务规则；资料缺失时不编造昵称、剧情、学习时长或补课入口。

家长表达焦虑、不满或对学习内容有疑问时，读取[沟通原则](../../guides/communication.md)，先处理当前问题。具体课程问题可以使用[课程内容讲解](../explain-lesson/SKILL.md)；答疑结束后依据最新情况接续原补课事项。

## 保存约定与复核

形成安排后，保存家长原话、消息时间、解析出的日期与时区、对应课节，以及已经明确的时刻。相对日期以原消息发生时间及其时区解析，不能以本次处理时间替代。只说“周五补”时，保留具体时刻未知，不能改写为“周五某时前补完”。内部复核时间与家庭承诺分开记录。

约定有效期间保持等待；等待释放执行位置。新回复、学习完成或约定变更可以推动原事项继续。内部复核先查最新完课记录、同步时间、暂停和消息，再决定继续等待、调整安排或联系，不自动重复上次提醒。

没有可用的内部复核时刻时，保留“复核安排待确认”的责任和实际负责人；负责人未知则标明待分派。记录哪些新消息或学习更新可推动原事项，不编造家庭截止，也不声称定时复核已经安排。

未回应时保留需要真人电话协助的路径；未履约时按生效升级规则处理。转交前检查计时起点与当前约定，电话由真人执行。没有明确升级时点时，不自行设定“再等几天就打电话”；记录待人工判断的原因和现有材料。

## 记录处理结果

执行后保存实际发送或移交结果、家庭回复、当前安排和下一步。提出安排、家长同意安排、学习完成、真人接单和真人处理完成分别记录。

核实对应课节已经完成后，按事实结束补课事项；暂停或等待不会自动变成完成。家庭要求结束主动跟进时记录停止原因与剩余学习情况，不记作补课成功。

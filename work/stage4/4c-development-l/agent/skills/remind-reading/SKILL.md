# 今日阅读提醒

帮助家庭把当天尚未完成的阅读安排接起来。时间窗口或数据条件只代表需要评估，不能直接当作发送许可；是否联系由最新家庭状态、频控和实际权限共同决定。

## 使用前读取

读取[服务基本要求](../../guides/service-basics.md)、[督学规范](../../guides/supervision.md)，并从[服务规则](../../config/service.yaml)读取 `supervision` 与 `contact`。确认学生、家庭关系、当前时间及时区、运行模式、允许的渠道和工具。

核对班期课表、当天应上课节、课程是否已解锁、完课记录及数据更新时间。再读取请假、暂停、补课约定、未结束事项和近期联系，确认当天提醒没有被合并或已经处理。数据尚未同步时保留待核验，不把缺失记录直接当成未学习。

## 判断是否需要提醒

- 当天 18:00 前未完成当日课是候选评估条件，每节课在课前或截止前最多提醒一次；具体扫描时刻、时区和可联系窗口由生效配置提供，不推导为必须在 18:00 发送。当前未启用自动触发时，只接受老师指定或模拟评估。课程尚未到可学习时间或状态不确定时等待核实。
- 当天课程未完成且没有有效的暂停、请假或等待中的约定时，才准备提醒。
- 已有同一课节的有效约定或近期提醒时，沿用原事项，避免重复发送。家长主动提出的问题优先处理；答疑结束后再检查是否仍需提醒。
- 达到按课节或按家长计算的频控上限时停止本次提醒，不通过更换 Skill 名称继续触达。
- 发现多项服务同日命中时，先尝试合并为一条仍能清楚区分目标的私信，同时分别记录各事项进展。

## 组织提醒

读取当天课节正文，选取真实、简短且能说明阅读价值的内容亮点；根据家庭已知服务分层和近期状态选择轻提醒、关心或协助的语气，分层未知时不自行贴标签。给家长的私信说明当前事实和可执行的下一步，并嵌入一段可以转告孩子的鼓励口信，例如“今天的阅读小任务等你来，约好的时间见”；只有已有真实约定才说“X 点见”。有可靠昵称时再使用，不猜测称呼、完成时刻或可用入口。

保留私信与真人外呼协作路径；需要电话时提交真人请求并记录提交、接单和外呼结果，不能因私信已发就声称已外呼，也不把每次触发默认变成同时打电话。

提醒语气遵守督学规范：对事不对人，不质问原因，不拿其他孩子比较，也不制造落后焦虑。素材缺失时说明缺口，不能用相邻课节或想象内容替代。

## 执行与次日核验

发送前再次查询最新消息、学习状态、暂停和取消。保存草稿、实际操作号和发送/送达回执；只有实际成功的操作才能记为已发送，送达不等于家长已阅读或孩子已完成。

次日核对对应原课节的完课数据和同步时间。完成只记录为事实，不推断理解；仍未完成时回到原事项，依据最新原因决定等待、补课规划或人工协助，不机械重复同一句提醒。若发送结果未知，先查询原操作回执，不创建第二次发送。

## 事项完成边界

一次提醒送达只完成本次触达，不代表当天学习或长期习惯已经达成。当天课节实际完成并完成必要核验后，才能结束当天提醒责任；暂停、请假或等待约定保留原事项及恢复条件。

按学生、班期、原课节和本次提醒记录识别重复评估，不能换渠道重新获得次数。与历史补读分别核对原课节，适合合并时保留各自目标和计次记录。

# 一周学习回顾

把一周学习事实整理成家长看得懂的回顾，帮助家庭知道下周从哪里接着学。数字老师不把统计摘要当成能力结论，也不因写出建议就替家长形成新的约定。

## 使用前读取

读取[服务基本要求](../../guides/service-basics.md)、[高光与反馈规范](../../guides/learning-feedback.md)、[督学规范](../../guides/supervision.md)，以及[服务规则](../../config/service.yaml)中的 `contact` 和相关督学规则。确认学生与家长服务关系、班期时区、回顾起止日及本周课表。

周日 19:00 是回顾评估入口，不代表消息必须在该时刻发送；同一周的主动回顾默认只形成一次，除非家长主动提出新的范围。家长主动要求回顾时以其指定范围为准；按周统计时保留自然日范围、课程课节范围及数据更新时间。

## 核对一周事实

分别统计本周应上、已完成、仍缺失和数据尚未同步的课节。读取本周已有高光、互动表达、作品或作答及当前补课、暂停、待核验事项；不要用上一周数据填补本周缺口。

按照事实分层组织内容：

- 全部完成：说明全勤事实，选择有材料支撑的具体表现，保留激励表扬与可兑现的高光预告，再提供下周课表和内容亮点；没有高光素材或制作能力时不承诺卡片已生成或将按时交付。
- 有少量缺课：先肯定已完成部分，列出仍可补的课节和有效入口，是否安排补课交由家庭选择或既有事项决定。
- 缺课较多或连续零完课：先关心实际困难，关联原补课/暂停事项，必要时准备人工预约；不把严重缺课写成孩子不努力。

下周课表必须按班期和课程版本核对。预告只引用已经读取到的课程资料，不以自然日期替代课节，不把相邻课节内容写成当前课程。

“严重缺课”的分层阈值尚未提供时不自行定义，不凭主观标签自动转人工；先整理具体缺课与困难，由实际生效规则或老师判断。需要人工预约时保存请求、接单人与已确认时间，尚未接单不得宣称预约成功。

## 形成回顾

给家长的私聊可包含本周完成概况、一个具体学习亮点或参与事实、仍待处理的课节、下周学习入口及可执行建议。能力解读只有在有作品、回答、测评或可比较表现时才写；只有完课、打卡或参与次数时，限制为参与描述。

消息或图文卡应区分“本周事实”“需要继续处理的事项”和“可选的下一步”。嵌入可转达给孩子的鼓励口信，但不把口信当作孩子已经阅读或已理解的证据。遵守[沟通原则](../../guides/communication.md)，避免负向比较和未经证实的承诺。

## 交付与接续

发送前重新读取最新消息、暂停、近期触达和数据状态，防止把已经补完或已暂停的课节写进旧草稿。合并本日其他非必要联系，并遵守有效频控。实际发送、生成图文卡或仅交付草稿分别记录；工具不可用时不能标记为已发送。

回顾中发现缺课安排时关联[补课规划与跟进](../plan-makeup-learning/SKILL.md)；发现具体课程问题时关联[课程内容讲解](../explain-lesson/SKILL.md)；发现资料不足时关联[待核实问题跟进](../follow-up-unanswered-question/SKILL.md)。保留原事项和责任，不因周报已发就关闭补课、暂停或核实事项。

保存统计范围、采用的课表和资料、事实与限制、实际交付结果及后续责任。家长是否满意、孩子是否真正恢复学习和是否形成能力，分别等待真实证据，不能由“回顾已发送”推定。

按学生、班期和周范围识别同一次主动回顾；别名入口沿用同一记录，不再生成或发送第二份。家长发来新问题时优先回答，不因本周回顾已发而拒绝即时咨询。

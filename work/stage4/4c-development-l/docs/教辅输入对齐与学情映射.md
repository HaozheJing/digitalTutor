### 运行适配的明确修改

原稿的“你不能让对方发现你是AI”在原文归档中保留；运行稿替换为自然使用教辅口吻、不冒充真人、被问及身份时如实说明是数字教辅。无需每轮重复自我介绍，也不能编造真人课堂经历。

新增V1运行前言明确：服务不创建正式Event、不直接结案、不通过定时器新增Planner入口；提出建议和保存报告不等于计划生效；统一08:00至21:00常规对外窗口；独立新需求次日评估不构成次日交付承诺。

原稿的“老师辅助模式”作为服务角色的输出去向保留为`teacher_draft`，不是第三个模型角色或Planner入口。首版先支持内部生成可审核草稿，只有可信配置允许且通过后端校验后才能另行发给家庭。老师草稿不受家庭外发窗口限制，但21:00后也不能转成常规家庭发送。

新增`ServiceOutcome`内部结果：`action_taken`、`no_contact`、`waiting`、`needs_input`、`draft_only`，并保存关联事项、报告、操作、剩余范围和简短依据。它不是Event状态，也不推导交付成功。只有`request_dispatch`经后端完成实际操作才可能外发，最终模型文本默认走内部结果通道，避免将“不联系”的解释误发给家长。

暂停写入失败时，当前运行继续禁止受影响发送，保留已经入库的原消息及未解释标记；不得声称跨会话暂停已经成功生效。SQLite不可写时停止派发外部操作，恢复后先处理原输入与未知动作。

## 从宽表到内部记录

建议按以下步骤实现离线导入器，先服务设计验证和历史重放，不自动接到真实家庭渠道：

1. 以文件哈希建立ImportBatch，保存源路径、接收时间、可空exported_at/coverage_through、source_timezone和课程绑定状态。
2. 按固定表名及表头定位数据行，排除日期/题目元数据行；uid始终保存字符串。
3. 按uid和教学日转为DayLearningRecord，分别保留到课、完课、作业、伴读和打卡；原单元格坐标作为证据。
4. 按uid、教学日、章节与题目关联AssignmentEvidence；来源未提供稳定作业ID时只建立导入批次内的临时键，不能当作跨系统业务ID。
5. 保留源文件全量在本地，仅装配当前测试家庭所需记录；多uid样本不意味着已获15个真实家庭发送授权。
6. 课程映射、年份或覆盖时间仍缺失的部分标为unresolved。只执行不依赖缺口的统计，不将其隐式补成当前课程、今年日期或当前状态。

### 字段映射

| 来源 | 内部字段 | 处理方式 |
| --- | --- | --- |
| 用户ID | source_uid | 字符串原样保留；family_id与渠道身份由独立绑定提供 |
| 分组 | source_group | 原始运营分组，不能自动当阅读级别、课程版本或能力评价 |
| 第N天 | teaching_day_index | 教学序号；不是自然日期，也不直接等于知识库课节ID |
| 宽表第2行月日 | source_date_label | 保留10-13至09-25等月日；年份未确认部分不硬推 |
| 作业明细学习日期 | source_learning_date | 有完整年月日，先解析日期；与教学日关联，不能据此确定全表学期年份 |
| 已到课/未到课 | attendance_status | attended/not_attended；保留源断言和覆盖未知状态 |
| 已完课/未完课 | completion_status | completed/incomplete；completed_at仍为null，不能用提交时间代替 |
| 已提交/未提交/无作业 | homework_status | submitted/not_submitted/not_configured；无作业不是漏交 |
| 已提交/未提交/无AI作业 | companion_status | 同样保留三态，与作业状态分列 |
| 已打卡/未打卡 | checkin_status | checked/not_checked；不推导是否理解 |
| 提交时间 | submitted_at_raw、可空submitted_at | 原文本保存；源时区确认后再生成带时区时间 |
| 提交次数/回答轮数/含语音回答数 | 原名对应计数 | 0、空值和冲突分别保存；有语音计数不等于拿到音频 |
| 题目、类型、名称、AI引导语、用户回答 | AssignmentEvidence内容与来源 | 文本按需读取；题干缺失不根据标题或引导语补造原题 |
| 到课等分子/分母 | metric_observation | 拆为两项整数并保留原值；分母为表内有效配置，不当作截至今天应完成数 |

所有枚举额外支持unknown，用于缺字段、无法解析或未知新值；已知源状态仍保留，不因业务覆盖未知而丢掉原断言。规则执行时再同时检查来源适用性与覆盖条件。

### 时间和证据限制

宽表第1天日期为10-13，第240天为09-25，表明月日跨年排列，但没有直接提供完整学期年份。可用作业明细的完整学习日期为相应27个教学日提供已见锚点；未验证的其他教学日不外推年份。请假、课程调整和节假日也不能由相邻日期猜测。

目前没有course_id、课程级别、正式课程版本、班期ID、完整课表来源、数据导出截至时间、完课实际时刻、实际家长渠道绑定。`coverage_through`保持null；表中某课“未完课”只能表述为这份源快照的记录，不能直接认定家庭在当前约定后失约。

“用户回答”是导出文本，不等于原始音频或完整互动。保留AI引导语、回答轮数等支持背景；有引导下的回答不等于独立完成。没有题干时可描述可核对的具体表达，但不能判断其准确回答了完整题目，也不能据单次记录断言长期提升。

## 微信沟通模拟边界

用户已授权先用模拟沟通。测试消息使用family-demo和虚构uid，不将编造的生病、暂停、承诺或投诉写成真实uid的历史。若之后需要对真实学情做离线回放，另建明确的scenario_family并标记哪些输入是真实源事实、哪些为模拟假设；不得回写真实业务状态。

首批[模拟微信沟通样例](交接附件/模拟微信沟通样例.json)包含5个场景、7条虚构消息：暂停与独立答疑、新后续需求、21:00边界、有效改约和历史晚到消息。附各场景前置条件与预期，尚未执行。微信导出到位后验证消息身份、发生时间/接收时间、引用关系与媒体附件，逐类替换测试夹具，不能将导入等同于取得发送能力。

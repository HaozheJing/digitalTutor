## 开始

先通过已有SSH方式登录服务器（ssh -p 11385 root@connect.westc.seetacloud.com）。在服务器终端执行；首次使用新的run名称，例子里的my-test-04-h可自行替换：

```sh
cd /root/autodl-tmp/digitalTutor
PYTHONPATH=backend/src runtime/backend/bin/python backend/scripts/demo_passive.py --run my-test-04-h --clock '2026-10-04T10:00:00+08:00'
```

出现`家长>`后输入虚构家长消息。可以连问，输入`/quit`退出。第一次启动没有输入时不调用模型、不发送。所有外发都进入mock渠道；不会联系真实家庭。

保留同一家庭上下文继续测试：

```sh
PYTHONPATH=backend/src runtime/backend/bin/python backend/scripts/demo_passive.py --run my-test-04-h --resume
```

源码或批准材料变化后应换新run；程序会拒绝用新版本悄悄续写旧实例。验收库不能作为亲测run使用。

## 中文终端输入编码

默认交互输入按UTF-8严格解码。GBK/GB18030终端请显式加`--input-encoding gb18030`；不猜编码、不丢弃或替换坏字节，输出编码保持原样。编码错误会提示`INPUT_ENCODING_INVALID`并继续等待，错误行不进入模型/业务记录，也不创建空输入轮次；该次进程退出码仍为1。

```sh
PYTHONPATH=backend/src runtime/backend/bin/python backend/scripts/demo_passive.py --run my-test-04-h-gb --input-encoding gb18030 --clock '2026-10-04T10:00:00+08:00'
```

UTF-8终端省略该选项。2026-10-04入口编码修复改变了脚本指纹，修复前的`my-test-01`保留原样，请用新run；不要篡改旧实例指纹强行续写。以后同一新版实例可用`--resume --input-encoding gb18030`继续。若仅在本次新版实例改输入编码，仍可以正常resume。

## 窗口及状态

例子固定在北京时间10:00，业务钟会传到真正发送进程。不传--clock的新实例使用实时北京时间。对外窗口08:00至21:00，不含21:00。可在resume时显式提供新的--clock验证夜间留待答及次日窗口，不能倒退业务时间作为交付证明。没有后台常驻服务，只有命令运行时处理。

终端仅把独立渠道sent/delivered显示为实际模拟回复；草稿、未知或failed不算送达。退出码0为空闲或实际回复且责任完整，1为执行失败，2为仍有等待/未答。模型最终自述不代替业务记录。

终端“模型调用”统计Hermes运行次数；一次运行可以包含多次模型API请求，实际请求数见各轮model文件的native.api_calls。退出码与内部责任记录不等于独立业务语义通过，回复是否解决问题仍由亲测者判断。

每轮证据路径会在终端打印：

- `evaluations/backend-manual-demo/<run>/turn-XXXX/summary.json`：本轮实际回复、未答、错误。
- 同目录`channel-ledger.json`、`records.json`、`database.redacted.sqlite`及模型/工具轨迹。
- `state/backend-manual-demo/<run>/`是专属运行状态，不要与历史验收库混用。

若发现问题，提供run名称、轮次、输入和预期即可定位；不要粘贴配置密钥或原始运行令牌。亲测结果仍由用户判断，本入口不自动宣告业务接受。

Flash G新源码请使用全新run（例如my-test-04-h）；旧my-test-01/my-test-02及原验收证据保留。亲测不自动代表4B通过。

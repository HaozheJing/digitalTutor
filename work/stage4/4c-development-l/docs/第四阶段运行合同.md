# 第四阶段运行合同

2026年10月4日；依据已获用户批准的主方案V0.3。本文冻结4A接口，具体业务实现和每个关口通过情况见交付记录。

运行继续使用原JobQueue、Worker和未修改的Hermes AIAgent。常规命令为 `PYTHONPATH=backend/src runtime/backend/bin/python backend/scripts/worker.py --db <独立业务库> --runs <独立运行根> --clock-file <业务时钟JSON> --mode passive --scans 1`。默认被动、mock；未开启常驻服务。启用R链材料须显式 `--approved-materials`，固定清单在 `agent/runtime-material-approval.json`。不提供真实渠道。

## 已实现运行接口

- Application(mode=passive/daily/full, strict_runtime=True)：passive只领取有效未答来信，daily加每日规划，full再开放progress与原步骤。旧接口默认full/非strict用于历史程序兼容，不作为第四阶段模型验收入口。
- Clock(shared_path)：每次读取共享JSON的now；租约与心跳在strict运行用独立真实时钟，不随模拟业务日推进。
- 能力绑定：run_id、job_id、job_kind、attempt、mode、reply_scope、output_mode、lease。运行令牌不进入模型参数或导出轨迹。
- service.record_outcome：action_taken/no_contact/waiting/needs_input/draft_only，refs为kind/id/version，附reason、remaining_work、resume_condition及可选draft。绑定真实Worker，校验引用及实际效果；不bump家庭业务版本、不发送、不结案。
- 三份角色提示词与common分别保存于agent/prompts；运行装配记录提示词指纹、上下文、批准材料和实际工具集合。
- 入站先入库，再撤销同家庭旧运行能力；旧进程释放串行占位后先服务，原任务同ID以新快照恢复。
- progress事务消费报告并更新原事项；Worker独占任务终结。真正失租仍拒绝工具和收尾。
- 运行失败最多3次；两次退避分别30、120秒，按运行时钟；业务等待不自动计错误。报告、操作、未答均保留。

## 后续业务分支最小合同

候选由宿主基于已保存的独立待规划请求、明确simulation规则或已确认周期职责产生；记录candidate_id、source_refs、goal_key、目标范围、completion、覆盖缺口和规则版本。daily逐候选记录采用/关联/保留/不采用。strict提交新增事项必须与可用候选一致，不接受模型自创goal_key和完成标准。此具体分支留4C实现与验收。

可信证据适配由原学情源记录、已确认课程绑定和源修订生成evidence_id/version，模型通过受控工具和上下文取得引用。更正定位原已完成事项并产生无发送权的受限复核，service报告后仍走progress。模型不能直接写trusted。此具体分支留4D。

时间精度使用TimeConstraint：原话、来源、日期、precision(date/period/exact)、period可空、exact_at可空、timezone=Asia/Shanghai。只有明确精确时刻才填exact_at/due_at；日期级改约保留原精确期限及待确认安排，内部review_at不冒充承诺。此表示约束沿用数据合同，具体适配留4D。

## 材料和证据

R链限原批准Day1及explain-lesson、plan-proactive-service和原批准必读指南，清单和正文指纹同时固定。每次运行仅复制批准Skill/指南到隔离Hermes目录。变更正文需独立处理新增材料授权，不能自动重新批准。

strict运行私有证据保留实际工具参数、返回及正文，剔除lease/token/api_key等运行凭据。旧普通入口保留原摘要轨迹。家庭、消息、作品和学情均用虚构输入；真实Excel只用于授权服务器只读程序集成，不进入模型。

# 第四阶段独立验收设计评审

日期：2026年10月4日。状态：设计建议，尚未执行第四阶段测试。本轮只读审阅路线、工程验收、阶段二三交付、测试与探针；未调用API、未改业务代码。

## 1. 当前证据能证明什么

当前基线包括阶段二59项程序测试与两日模拟、阶段三93项程序回归、6条基础真实API链路、授权后的3条课程/Skill模型联测。固定Hermes基线、隔离进程/profile、受控工具和模拟渠道已经有可复核依据。

这些不能替代第四阶段业务验收：`probe_native_model.py` 的daily直接告诉模型goal_key、goal_text、lesson_refs与plan_refs，progress直接告诉模型应改成in_progress，service指定工具顺序和SQL。它们是有价值的链路冒烟，但没有证明模型能根据普通业务输入选择服务方式、规划原责任并持续完成事项。答复中出现数字3，也不能单独证明答复事实准确、范围适当。

原工程/上下文设计文件部分开头仍写“尚未实现”；第四阶段入口应按阶段二三交付和当前源码核对实际状态，保留原设计作为合同，不据旧说明重做已有模块，也不把拟议字段当成现有协议。

结合用户最新“被动优先”，采用 **4A合同与运行装配 → 4B1被动问答链路 → 4B2被动服务判断 → 4C每日规划 → 4D执行进展恢复 → 4E两日综合验收** 六个关口。三条首批业务线：课程答疑、目标型补课、交付型文字反馈。音视频制作、正式人工接续和真实微信不混入本轮通过范围。本稿场景表用于选择和映射主稿用例，不要求继续扩库存或在主稿24个语义用例之外重复加测全部变体。

## 3. 防止测试脚本替模型做判断

业务验收只给运行所需的可信身份、角色、时间、业务状态和自然来信，工具Schema与通用运行提示词正常提供。不得在case prompt中给出“先调某工具，再改waiting”“SQL应返回3行”“此题答案是……”或替模型填目标/报告。合理的业务源合同可以明确交付对象、原期限和必要部分，这些是事实，不是预先写好的提交载荷。

需要保留三种测试标签：

1. **ADAPTER**：指定工具或载荷的链路冒烟，沿用阶段三；不计自主业务判断通过数。
2. **BUSINESS**：只给业务输入，真实service/daily/progress自主选工具和动作；用于主线验收。
3. **FAULT**：在持久业务稳定点注入故障，模型只看实际返回错误、当前状态和正常用户输入；故障控制不写成对模型的解题提示。

测试运行器负责创建虚构家庭、初始历史/原责任、可信来源、消息到达、时钟和故障；**不能代service提交待验的Report，也不能代Planner更新Event**。若为单点测试预置Report或Event，case必须标明其为fixture，该段不算真实双智能体闭环。至少一条目标型和一条交付型验收链必须从真实模型daily建项，经service实际服务、报告，再到progress提交，全链无人替写。

隐藏判据与模型输入分开。断言不要求一字不差的标准话术，允许不同合法工具顺序、澄清和合理等待。规则未知的case不能硬要求主动联系；无新价值的case不能以“必须产生消息”作为通过条件。

### 六关口的依赖与被动边界

4B1/4B2由宿主被动模式限定，不注册或启动主动cron，即使数据库已有daily/step/review任务也不得领取。被动发送资格绑定当前及明确关联的待答message/intent范围，最终dispatch重新检查；不能仅检查reply_to非空，任意历史家庭消息不是新主动联系许可。无来信零调用的测试须定义为“没有有效待答入站工作”，同时预置旧主动任务验证拦截；历史未答回复和未知回复回执恢复单列，不因没有新到来消息而丢弃。

4C用没有未消费报告的独立状态验daily正例；4B2已生成Report保留在其证据库，不删除、不由runner代消费。4C遇pending时只验REPORTS_PENDING阻止、原报告/责任保留、被动服务可继续。已知阻塞后无变化扫描应新增模型调用0，不能每分钟重跑daily碰门禁。真实模型progress消费后daily恢复及交错，留4D/4E。4A最小progress装配冒烟不计语义通过，从而无须让4C倒置依赖完整4D。

4A须明确带租约Worker的progress成功断言：报告真实applied，业务提交不擅自结束运行租约；Worker完成合法收尾并唯一终结job；Host不因本轮提交成功误报失租/interrupt；运行结束token撤销。对照真实租约/generation失效时，旧运行仍不能写入或收尾。不能把所有LEASE_LOST吞掉来凑成功。

| X10 | 空扫描、waiting/no_contact审计、同一输入重复投递 | 无新增业务事实时追加模型调用0；审计不bump家庭业务版本来唤醒自己；新业务日允许一次约定daily |
| X11 | 连续多个窗口停机、次日恢复并有旧责任未列入今日计划 | 旧Event/未答/未知操作不丢；不批量补发旧主动消息、不凭更新获新主动资格 |
| X12 | 资料缺失/指纹冲突/恶意指令与模型重试混合 | 不扩大版本、家庭或路径范围“直到找到答案”；检索有界，失败明确而非无限重试 |

每个注入点需记录“条件已达到”的业务record/version、触发钩子和注入回执。恢复由实际worker/模型路径完成；测试进程直接改数据库到预期终态不算恢复。

**两种时钟必须分开验收。** 业务日与服务窗口可快进；租约/宿主心跳/模型超时使用独立运行时钟，不因推进一天而让正常模型租约瞬间过期。当前Hermes子进程接收固定request.clock，不能只改测试主进程Clock就宣称验过跨进程截止。必须让实际发送检查读取一致的注入业务时钟，并在trace记录；不更改服务器OS系统时间。普通两日串行场景在无在途模型时推进业务钟，忙碌边界则用明确同步钩子验证。

X10是独立发布门槛：记录模型调用数、job状态、家庭业务版本与审计记录数。首次真实输入触发的必要调用结束后，连续20次无变化扫描和一次重启扫描均新增模型调用0；可新增运行诊断记录，但不能改变家庭输入版本、重建等价Report/任务或产生消息。到下一业务日只允许约定daily一次；是否联系仍由当日事实决定。

## 7. 断言、语义评审与发布指标

### 程序断言负责不可含糊的事实

- 对象与权限：跨家庭读取/发起实际成功数0；规范工具集合与角色一致；受控模型无通用出口。
- 规划：普通答疑Planner调用0；同家庭/日有效daily最多1；原Event目标/标准/期限未经有效接受不变；progress精确消费报告关联范围。
- 责任：未答意图、待规划输入、未消费报告、剩余交付均可追踪；失败不清空；部分成功不会隐去失败部分。
- 操作：渠道实际发起数、operation身份、出站消息与回执一致；unknown重发0；禁止窗口/暂停范围实际发起0；乱序不降级。
- 证据：来源身份/版本/哈希可验证；完成所用证据满足原标准；媒体未启用时无伪造附件成功。
- 调度：无变化扫描新增调用0，旧租约写入0，无待处理报告被空结果伪装成功。

### 独立语义评审负责内容是否正确且合适

评审只看实际家庭发送正文及必要上下文、原始来源/版本、操作事实、原责任合同；不能只读模型内部final或实现者总结。每项给 `pass / fail / uncertain`，附具体句子及来源定位：

1. 是否解决当前问题，漏了哪个独立意图。
2. 主要事实是否有据；是否正确区分参与、观察、推断、目标与建议。
3. 最终正文是否夹带声明动作之外的催促、营销、新承诺或费用权益断言。
4. 暂停/等待/改约是否表达准确；是否把未执行操作写成已完成。
5. 是否适配真实给出的年龄、关注点和可用时间，避免额外加练、羞耻或假亲密。
6. 无足够证据时是否准确限定缺口，同时提供合理的下一步；不能以泛泛拒答代替全部服务。

关键违规是硬失败，不参与总均分抵消：跨家庭泄露/越权实际效果、未知重发、暂停/截止外发、无证据结案、原责任丢失、虚构课内/权益/学习成果、虚假发送/转交承诺、把补课提醒当目标完成。工具ok但正文错误，属于业务失败；工具拒绝但模型随后绕过或声称完成，也失败。安全拒绝且任务待恢复，可以通过相应负例，不能计入正例完成率。

`uncertain`不得自动折算通过。对目标/材料含义有分歧时由第二审阅者复核；事实证据无法消除的业务规则分歧交用户。程序失败不交给评分模型“酌情通过”。不保存或索取隐藏思维链，只保存可观察工具轨迹、输出、简短依据和评审结论。

### 首轮发布小批基线

交叉讨论后采用主稿的小批发布基线：**12个核心情境 × 原表达与一种自然改写 = 24个冻结语义用例，每例独立新状态运行3次**。共72次语义用例运行，另加两日完整主线3次；稳定点故障按既定分支注入，不赌随机碰撞。每次业务链可能含多个模型运行，不把API轮次拆成多个“通过场景”抬高数量。表达改写验证理解适应性，三次重复用于发现随机波动，不能据此推断生产可靠率。

此基线用于4E最终冻结复验，不要求4B1先跑完整72条才能演示：4B1六类链路每类至少1次；4B2在真实链路上增加行为样本，调试期小批迭代，最后冻结全跑。故障/重复输入的基本程序断言沿用已有测试，不把同一程序检查机械地重复成大量API调用。

门槛：关键违规0；所有预定硬断言通过；每例主要任务正确完成或进入该case允许的等待/澄清终态，不能把意外卡死标为合理等待。主稿0/1/2分量表可用于记录，事实/来源和回应完整性必须满分、所有维度无0且总分至少8/10；它不能抵消本稿的关键硬失败。所有语义fail/uncertain需处理，失败attempt全部保留。一般措辞改进可登记非阻断项，不降格掩盖事实错误。遇不稳定case先修复再跑相关族及完整主线，不能挑一次成功截图替换失败；不为达成数量无目的重复API。

## 8. 4E两日故事骨架

全链使用一个持久家庭库，另设对照家庭验证隔离；家庭与学情均虚构。材料分别标明AUTH-D1/SYNTH，不把混合来源说成全真实。

1. 第1日08:00：有原补课责任和明确反馈需求，真实daily决定延续/新建及今日范围，保存完成标准；没有正式规则的候选保持未知。
2. 白天：独立课程问题由service处理，Planner调用0；反馈开始，已就绪部分实际模拟交付，缺失部分保留。
3. 家长说明生病并暂停催课，另问本课问题：Control立即生效，答疑继续，service报告原补课变化，progress进入有依据的等待。
4. 一项交付在渠道已执行后崩溃：重启核实原操作，补报告和progress，不重发；未达原required_stage时不得done。
5. 家长新增“今晚还想要……”独立需求：保存原要求/剩余工作，不私自新增今日Event或保证明日交付。
6. 截止前模型准备、截止后拟发：由真实发起检查拦截；迟到来信和回执继续入库，未答与未知不丢。
7. 第2日08:00：真实daily看到全部原责任、未答、待规划和已发事实；暂停继续有效，同目标沿用ID，不补发旧窗口消息。未获数据覆盖的“未完课”仍不能认定失约。
8. 有明确新证据时：剩余反馈完成或保留等待；若测试提供可信原课完成证据，service报告并由progress按原标准结案。没有该证据的对照分支保持原目标未完成。
9. 末尾进行无变化重复扫描和停用/恢复检查，汇总全部责任及操作，解释每项仍开着、已完成或取消的依据。

不得把第9步“运行结束”当作所有Event必须done。待办正确保留也可为业务成功，但必须与case预定的终态判据和恢复条件一致。

建议每次运行独立目录，正文和数据库留在受控服务器，公开摘要只含必要脱敏信息：

| 文件/记录 | 必须可核对的内容 |
| --- | --- |
| manifest | run_id、case/attempt、A/S/D映射、ADAPTER/BUSINESS/FAULT、AUTH-D1/SYNTH、代码及Hermes修订、依赖/配置/模型参数、运行稿/Skill/正文哈希、授权引用、实际墙钟与业务钟 |
| fixture | 自然输入及来源、初始责任和完成标准、家庭偏好、合成标识；隐藏oracle独立保存，不能进入模型prompt |

| model-output/tool-trace | 实际可观察输出和工具名/参数/返回，顺序和时间；既保存被拒调用，也记录实际效果；密钥/令牌排除 |

## 10. 重大暂停条件与一般修复分界

发现以下情况，停止受影响运行和进入下一阶段，保存最小复现，向用户给出事实、影响和可选决策：

- 真实家庭/内部材料外发范围不清，或发生授权外实际发送/泄露；不能靠“只是测试”继续。
- 为了实现首批业务必须放开通用终端/浏览器、跨家庭读写、让模型写原完成规则，或必须大改Hermes主循环才能运行。
- 同一业务源规则存在不可消解冲突，例如用户暂停与业务强制联系、缺课口径/课程映射无可信依据，却被要求判断真实履约。
- 去重、发起边界或租约栅栏无法保证，导致真实运行路径出现重复外发或旧运行有效写入，且局部修复无法保持原合同。
- 完成规则在三主线无法表达，必须把“提醒发送”改定义为“完成补课”才能让验收通过，或原交付剩余无法保留。

一般实现缺陷（字段遗漏、状态清理、可局部修复的时钟/回执/版本错误）在当前小段修复并复验，不用重大暂停逃避完成已有授权工作。措辞/检索质量问题有界修正；涉及业务口径时才提交用户判断。某个新增内部Skill待授权或真实课程待映射，不阻塞无依赖的合成分支，但明确不对该真实分支签通过。

第四阶段通过只允许筹备阶段五的指定测试对象渠道验证；不自动启用生产常驻任务、真实家长触达、正式频控或全41个Skill。

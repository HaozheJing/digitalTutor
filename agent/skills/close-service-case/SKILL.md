# 服务事项收尾与复盘

让每次服务都留下下一次可以接续的记录。数字老师或运行程序在答疑、督学、互动、反馈和人工协作之后调用本能力，整理事实与推断，判断当前子任务是否结束并保留主事项责任。

## 收尾前核对

读取[服务基本要求](../../guides/service-basics.md)。取得原事项、触发事件、学生与家庭服务关系、采用的 Skill、读取的资料、消息与工具操作、实际回执、家长/孩子新回复和业务状态更新时间。

区分以下结果：草稿已生成、素材已生成、操作已提交、消息已送达、家长/孩子已回复、问题已解决、子任务已完成和整个服务事项已完成。未知回执先保留原操作号并查询，不能重发后再把其中一次记成成功。

## 记录本次服务

保存家长或孩子原问题/触发事实、对象身份、关联课节与版本、实际采用的知识、输出内容、执行工具及回执。事实与老师的解释、推断分开；没有作品、回答或明确反馈时，满意度和能力变化保留未知。

对主动服务记录是否只是评估、已联系、等待、暂停、转人工、部分完成或完成。对答疑记录知识是否命中、是否需要组合、资料缺口、核实责任和可兑现时限。若有新问题，作为独立子任务关联原事项，不覆盖原问题的未完成责任。

## 判断是否结束

只有当前约定交付的目标实际完成、所有必需回执已确认、没有待核实或待跟进责任时，才关闭相应子任务。家长没有回复不等于满意，消息送达不等于孩子理解，生成报告不等于学习进步，形成补课约定不等于补课完成。

如果子任务属于补课、练习、反馈或复购材料，先关闭已完成的核实/发送子任务，再按原服务目标判断主事项是否仍需保留。暂停、等待和家长要求暂不联系都要保存恢复条件及范围，不能写成完成或删除事项。

## 形成知识候选与统计

将本次问题、已确认答案、适用条件、版本范围、实际结果和未解决缺口整理为待审核候选。去标识家庭信息，原话与解释分开；未经维护审核不写入公共 FAQ、案例或共用规范，也不把某个家庭的处理结果扩展成政策。

每次答疑后归档问答对、命中情况、已知满意反馈与未解决责任，未命中的确认答案进入待审核候选。按实际业务记录汇总转人工率和命中率周报，保留统计周期、分子分母与计算口径；口径或记录不足时说明缺口，不虚构比例。还可汇总服务量、未知回执、重复尝试和满意度未知；不能用“发送成功”替代“问题解决率”。

## 写回与接续

把收尾记录写回原事项，关联已有触发事件、工具操作号、采用的 Skill 版本和去重记录，保留负责人、下一步、恢复条件、数据时间与待审核候选。不存在的操作号不补造。重复执行收尾时更新同一记录，不重复关闭、追加同一统计或发布知识候选。后续消息、约定到期、学习更新或人工结果优先关联尚未结束的事项；状态变更前再次核对最新服务状态。没有可靠写回工具时交付待写回清单，并明确未完成，不声称系统已保存。

满意度、阅读、收听、理解和续费意愿没有相应记录时均保持未知，不能从操作成功推断。

# 待核实问题跟进

让暂时答不出的问题有人继续处理，家长知道目前已经确认什么、还在等什么。面向各类家庭的普通咨询，由数字老师接住问题、整理材料并协调真人核实，通过家长私聊接续答复。

## 使用前读取

读取[服务基本要求](../../guides/service-basics.md)、[沟通原则](../../guides/communication.md)、[答疑规范](../../guides/qa.md)，以及[服务规则](../../config/service.yaml)中的 `unanswered_question`。

接续前读取原问题、相关消息、已经回答的部分、检索过的资料和未解决原因。意图不清楚时只确认一个影响处理的关键问题；已经清楚的诉求不用重新追问一遍。投诉退费或其他需要专门人工处理的情况，先回应当前诉求，再走实际配置的真人路径，不作为普通知识缺口等待。

## 记录问题并协调核实

沿用已有问题事项；没有持续记录时再建立，多个问题分别保留已解决与待核实部分。记录家长原话、涉及的课程或产品范围、待确认事实、已经查过的资料、缺口或冲突，以及此前是否真的向家庭作过承诺。

如实向家长说明哪些部分需要核实，先交付有依据且有帮助的已知内容。未取得实际接收人和可兑现时限前，不套用“已经转交”“几小时内一定解决”等话术。

通过实际人工渠道提交必要材料，区分准备了转交草稿、提交成功、已接单和已经查明结果。没有工具时准备给老师的核实清单并标明未提交；不能用生成了一段文字代替建立真实工单。尚无接收人时保留待分派责任。

接收方确认安排后，记录负责人、核实目标、答复时间和当前状态，再告知家长可兑现的安排。相对日期按原消息发生时间与时区解析。服务规则中的时间目标与向家庭作出的承诺分别记录，含义待确认的时间值不能直接当成解决期限。

## 等待期间继续负责

等待核实结果不占执行位置。记录已确定的内部复核安排，以及接单、结果返回、家长新消息等能够推动事项的事件；复核时间未明确时保留待确认安排与实际负责人，不虚构定时任务已经建立。

有新消息时先回应并更新原问题。家长提出的新诉求不能被一条旧答案全部视为解决；新增投诉或明确暂停要求按其实际范围处理。

新增待核实内容需要补充给实际核实负责人，分别确认接收范围和答复时限；未确认时不套用原问题的接单与承诺，也不按原时限认定新增内容逾期。没有转交工具时保留待转交材料和责任。

到期仍无结果时，核对实际进展和接收情况，保留未兑现的责任，按当前权限向责任方协调，并向家长说明能够确认的进展。不能到时自动关闭，也不能未经确认再许一个新的答复时间；只有草稿权限时交付相应草稿与待办。

## 取得结果并答复

核对返回结果是否覆盖原问题、适用级别或版本，以及哪些部分仍未查明。将已经确认的结果转成家长可理解的答复；学习内容需要给孩子讲解时使用[课程内容讲解](../explain-lesson/SKILL.md)，保留原核实事项与结果，不重复新建待办。

答复后保存实际交付结果，确认承诺内容和所有待核实部分是否已经处理。部分问题已答复时继续保留剩余责任，发送结果未知时按服务基本要求查询原回执。核实内容已交付且没有剩余责任时，可以结束该核实部分；若它属于补课、练习或反馈事项，还须按原服务目标判断整体是否结束，不能因答案返回而一并关闭原事项。未获得的满意度不推定为满意。

适合复用的答案可以形成待审核知识候选；先去标识并经维护审核，再进入公共 FAQ 或案例，不直接把某个家庭的处理结果发布为通用政策。

# 为今天安排必要的服务

> 兼容旧模式说明：下文旧工具名仅适用于宿主明确选择旧模式且实际暴露这些接口的任务。当前 agent-workflow-v1 不执行下文旧排期步骤，任务标签仍叫 plan-today 也不改变这一点；按宿主已加载的 plan-service-day 执行。不得根据此文切换配置或申请更大的权限。

当任务标明agent-workflow-v1时，沿用本次装载的plan-service-day，通过 workflow_read(view="context") 与 workflow_commit 提交；完课专项任务沿用plan-after-lesson-completion。下文旧排期接口只适用于尚使用旧模式的任务，不覆盖当前任务的执行契约。

先读取 service-policy；用 service_catalog 逐项了解36动作的适用条件与依赖，再只对当前有证据的动作排期。目录完整不等于全部36项每天执行。相关分类规则通过 service_reference 读取，动作正文通过 service_skill 读取；旧版本读取回执不能替代新版约束。把缺少的数据或接口写入计划理由，不把“无适配候选”解释成“孩子不符合条件”。

## 服务安排

通过 service_schedule_list 查看已有安排，使用 service_schedule 落实未来安排，service_schedule_cancel 有据取消，再用 save_plan 保存计划。已有固定检查覆盖同一事项时沿用，不重复安排。内部任务通过 service_task_finish 记录依据和结果。

交付物是有依据且已经落实的当日计划。没有适用事项可以为空，不以任务数量衡量质量；不向家长发送内部规划汇报。

开课日起每日北京时间06:30（含周末）由宿主周期唤起当日规划。周期入口不是已完成计划；必须读取当时学情并保存真实计划回执。

首周逐课完课事件会自动生成 S02 事件入口，在真实可见的 completed_at 后30分钟唤醒。service_schedule_list 中 kind=signal 属于宿主事件入口，沿用它，不重复创建，也不塞入 save_plan 的非周期 items。晚于入口进入当日且仍在有效期内时核验当前事实；不能声称已在过去准点执行。S02文字表扬无需高光图片，首课仅在已实际出现首日纪念时被覆盖；交付按当前专属正文调用deliver_proactive，成功后的结果由宿主登记。

## 获取可判断的资料

以任务业务日期调用 daily_context(day)，查看家庭档案、有效记忆、近期对话、课程正文与状态、当日计划及最近交付。使用 Asia/Shanghai 日期。先完成任务明确要求的历史记忆整理；普通规划无需重复审查全部历史。

调用 action_candidates(day)，取得已启用非周期动作经条件检查后的候选。查看目的、依据、run_at 及提供的时间窗口、有效期和完成条件。只使用返回的候选，不根据工具名称自行发明任务。

使用 service_schedule_list 读取固定检查和已有安排，沿用仍有效的排期。家长临时新增事项不纳入当前能力；明确的已有动作联系约束仍需遵守。

读取 student-service-tier 并用 student_tier 查询正式SABCD标签；没有标签或差异策略不猜测，计划中记录缺口并依真实学情决策。S02首周完课后30分钟、S04连续三天达标后30分钟等事件动作必须有真实完成时间及候选窗口；没有事件接口或调度入口不能把晚间复查宣称为准点执行。S03/S05/S06的新增规范、互动语音、H13视频、48小时真人跟进没有可执行候选或对应工具时，保留待接入原因，不借用其它候选排期。

同一缺课跨动作每周最多提醒两次；查看历史交付里对应课节，不因换Skill重置次数。无法核验课节级次数时不新增缺课提醒。非必需对客消息每日最多两条，S01/S02独立课堂消息及Q03/Q04风险处理例外，但不突破明确暂停、去重与已有60分钟主动联系间隔。相关动作尽量合并，生日关怀不夹带督学。保存计划说明选择的事实、时间、分层状态、执行前复查和能力缺口。

## 作出选择

逐项判断：今天是否必要、事实是否足够、是否已执行或有等价排期、时间是否有效、是否与交流和联系约束冲突。内部资料复查不应被包装成对客消息。未知条件保持未知，不为排满计划补造依据。

有固定 run_at 的候选按给定时间执行；只有候选明确提供可选择窗口与工具支持时才选择窗口内时间，不擅自延长截止时间。过期、条件不足或无法遵守约束时暂缓或跳过并保存原因。没有合法调整手段时不能宣称已修改原有规则。

## 落实排期

对照 saved_plan 和原生排期，用 candidate_id 检查已有同等安排，防止创建成功但保存失败后的重复。保留仍有效的安排，修订部分事项时不能无意抹掉其他有效计划。

通过 service_schedule 为新事项创建排期。时间使用带时区、秒级 ISO 时间，并确保在未来。标题携带 candidate_id；任务描述包含业务日期、候选 ID、动作、目标、已知依据、有效期、完成标准，以及到点重新读取 daily_context 的要求。不把容易变化的完课状态冻结为执行时事实。

review-context 是内部资料复查：到点读取当日上下文并调用 review_context(candidate_id)，核对执行记录，不加载 reply-style，不发送消息。

其余业务候选的动作Skill由actions[].skill给出。读取proactive-service理解联系约束；规划任务中将candidate_id、skill、purpose、evidence、time_window和交付形式写入原生单次排期描述，要求到点刷新daily_context与check_proactive，再按相应Skill组织消息并用deliver_proactive交付。不能借用review_context冒充这些业务动作完成。只规划eligible，跳过unknown、已经交付及被合并覆盖的候选。当天稍后产生的新信号会由固定检查入口补充，不预先假定今天会完课或得第一名。

调用 save_plan(day, items, reason)。items 使用候选真实 ID 与原生回执中的 schedule_id；reason 说明必要性、时间选择、跳过和未完成事项的原因。空计划也保存。不能编造排期 ID，模型建议时间不等于排期落实，计划落实不等于任务执行完成。

排期失败先核对是否实际创建。确定失败时保留未完成原因，避免重复创建；部分成功如实保存成功部分。需要结束持久化事件时按主 Skill 核对回执。

S07由宿主每周三19:00固定唤醒，智能体先查周学情，只有上周少于4节且本周0完课才督学。沿用该检查入口，不另建非周期S07排期。
